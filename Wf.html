OH Wrike Workflow Visual Guide

The following outlines how project and task statuses are grouped and when each status should be used in Wrike.

Introduction

This quick reference guide is intended to help OH teams consistently understand and apply project-level and task-level statuses in Wrike and determine how statuses are grouped, what each status represents, and when updates should be made.

Project vs Task

This comparison explains the difference between Project and Task workflows.

Project-Level = The Big Picture

  • Represents the overall campaign or initiative lifecycle
  • Helps teams and leaders understand where the full project stands
  • Updated by Project Management

Task-Level = The Actual Deliverable

  • Represents the state of an individual asset or assigned task
  • Shows whether work is ready, underway, waiting, in review, or done
  • Updated by the assignee and/or Project Management

Key Team Reminder

  • A project can be in Execution while different tasks are in To Do, In Progress, or In Review
  • Project status and task status should support each other, but they are not the same thing
  • Always update the status that best reflects the current level of work

Project-Level Workflow

Project statuses reflect the overall lifecycle of the campaign or initiative. Project Managers update project-level status.

Deferred Backlog, wrap-up/reporting, or intentionally paused work

Portfolio Backlog

  • Default status for new request submissions
  • May mean that it is pending intake review or on the backlog to get started

Reporting

  • Campaign is live
  • Monitor performance and minor optimization
  • Complete reporting, lessons learned, and archive steps

On Hold

  • Project is paused longer-term
  • Add context in comments or description
  • Move back to active status when work resumes
Active Work is being planned or actively executed

Planning

  • Refine brief and requirements
  • Confirm assets, channels, dates, and metrics
  • Build Wrike plan and align internal resources

Execution

  • Assets are actively being produced
  • Cross-team work is underway
  • Continues until deliverables are launch-ready
Completed Project is formally finished

Complete

  • No more active work will occur
  • All tasks should be completed and marked Done
  • Supports accurate reporting and closure
Cancelled Project will no longer move forward

Cancelled

  • Project will not be completed
  • Related tasks should be cancelled
  • Document the reason in comments

Task-Level Workflow

Task statuses reflect the state of the actual deliverable. Assignees and project management should update them based on current work.

Deferred Work is intentionally not moving right now

Backlog

  • All blueprints start here
  • Used during project management planning
Responsible: Project Management

On Hold

  • Task is paused longer-term
  • Use for priority shifts, resource limits, or initiative pauses
  • Do not use for short dependencies
Responsible: Project Management
Active Ready, in progress, blocked by dependency, or in review/revision

To Do

  • Task exists, but work has not started
  • May be assigned or unassigned
  • Use for new or future-start work
Responsible: Project Management

In Progress

  • Work is actively underway
  • Update when the assignee begins execution
Responsible: Task Owner

Waiting On Input

  • Work is paused for a specific dependency
  • Add comment with what is needed and from whom
  • Return to In Progress once received
Responsible: Task Owner / Project Management

In Review

  • Task is with a reviewer or approver
  • Use for content, design, build, proofing, testing, or approval
  • Reviewer should approve or request changes
Responsible: Project Management

Changes Required

  • Review is complete and revisions are needed
  • Doer addresses feedback
  • Move back to In Review when resubmitted
Responsible: Project Management
Completed All work is fully finished

Done

  • All task work is complete
  • Subtasks and approvals are finished
  • Task moves into the Completed group
Responsible: Task Owner / Project Management
Cancelled Deliverable will not be completed

Cancelled

  • Asset or task is no longer moving forward
  • Document the reason in comments
Responsible: Project Management
